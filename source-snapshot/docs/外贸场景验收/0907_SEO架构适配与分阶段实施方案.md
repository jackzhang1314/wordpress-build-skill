# SEO 架构适配与分阶段实施方案

日期：2026-09-07。先完成本方案，再开展下述实施。

## 1. 本轮代码核查结论

现有 Agent 以 ToolHost 串行执行、SDK 工具审批、对话持久化、版本化文件、按需 Skill 加载为基础。工作区 JavaScript 无网络/Node/Python；外部 API 必须由扩展内固定工具调用。页面 inspectPage 提供渲染 DOM 证据，不提供全站爬虫或 GSC 的索引事实。

上轮 DataForSEO 原型已有集中配置、七类查询与十个 Skill，但缺专门验收。发现需完善：响应脱敏直接操作 JSON 文本可能破坏数据；成功文件与对话回执分开保存时存在恢复缺口；缓存未附文件版本/完整性；默认元数据注册依赖数组下标，后续维护易错；文章/域名存在重复入口。

代码依据：connections/dataforseo.ts、seo-tools.ts；skills/builtin.ts、store.ts、catalog.ts；runtime.ts、storage.ts；files/store.ts；tests/apify-maps.test.ts、skills-catalog.test.ts。

## 2. 本轮实施边界

交付首批九个具备现有执行基础的 SEO 入口：关键词研究、SERP 分析、文章工作室、竞品与域名分析、内容缺口、主题聚类、文章更新、已有 On-page 检查、已有技术页面检查。

十个数据型原型整合为七个：简报/数据文章/关键词文章整合为文章工作室；域名分析/竞品研究合为一个入口。保留旧版本用于历史任务，旧名称兼容到新名称，不能删除历史任务所需技能正文。

Backlinks、OnPage 全站云任务、GSC、性能、邮件与定时监测属于后续模块：本轮不把尚无工具支持的技能列为可执行入口。完整十八个 Skill 是路线图，不是假装现在全部支持。

## 3. 架构决定

- Skill：输入、方法、实际工具、输出、未知项；复用既有文件与浏览器，不引入 MCP/终端依赖。
- DataForSEO：共享账户配置；固定主机和七个白名单查询；免费账户验证与付费请求区分。
- 执行：沿用现有付费审批，不绕过只读模式；默认有界查询，不擅自循环分页。
- 证据：保留来源接口、请求、时间、费用、task ID、结果与覆盖范围；回执附实际文件版本与内容哈希。
- 恢复：发请求前持久化；未知结果不重复付费；若文件已经落盘但回执没写完，从匹配请求的文件恢复；成功缓存回读核验。
- 凭据：只在受信任本地存储和请求头存在；递归清理解析后的字符串，不替换 JSON 语法/数字；异常不回传远程正文。
- 包：稳定名字注册，显式绑定元数据和许可证；活动入口与兼容旧包分离，维持导出可往返。

## 4. 实施步骤与验收

1. 修复传输脱敏与数据文件回执/恢复；新增测试覆盖账户更换、删除、HTTP/业务错误、空值、未知提交、缓存和落盘恢复。
2. 重组技能入口，明确简报/全文/更新的交付，核查实际工具名和包内引用；验证旧名称/历史版本兼容。
3. 验证连接器授权页与技能依赖跳转：集中配置、密码不回填、关联技能准确、返回原详情。
4. 运行 typecheck、lint、相关测试和 build；使用预览检查前端。没有真实凭据时不冒充真实服务已验收，也不发起付费测试。
5. 保存实施记录与验收结果。公开 GitHub 发布放在后续模块定型后执行；本轮不推送整个混合工作区。

成功标准：九个真实入口、一个共享连接器、完整导出、可追溯数据回执、失败不重复扣费的测试证据、前端能找到技能和配置。

## 5. 后续模块的前置条件

| 模块 | 前置工作 | 验收要点 |
|---|---|---|
| 外链 | Backlinks 权限/价格、列表与交集工具、现场核实 | 来源页/目标/rel/上下文；无链接数效果承诺 |
| 全站审计 | OnPage task POST、轮询、分页、停止、预算范围 | 提交未知不重发，覆盖页数与终态明确 |
| Schema/国际 SEO | 固定 JSON-LD/hreflang 读取 | 原字段、跨页回链与渲染范围 |
| 性能/索引 | Google 或对应 API 适配 | 实验室、现场、索引三类证据分开 |
| 外联/监测 | 邮箱连接器、发送记录、停止联系、调度 | 授权/回执/幂等与失败恢复 |
| GitHub | 标准源码、许可、脱敏示例、安装验证 | 同一来源生成插件包与公开包 |
