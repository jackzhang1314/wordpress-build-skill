# SEO 完整实施补充方案

日期：2026-09-07；在新增代码前保存。承接首批九个入口与十八个目标技能，完成原方案剩余模块，不把文档入口视为底层工具实现。

## 工程顺序

1. 扩展受控 DataForSEO 请求协议，区分 live、异步提交、免费结果读取和停止；复用凭据绑定、版本化证据、提交前持久化与未知结果不重发。
2. 增加 Backlinks 画像/列表/锚文本/引用域/交集/变化数据；OnPage 提交、状态、分页、重复标签/内容、内链、跳转链、原始 HTML/结构化数据、停止；单页云检测和 Lighthouse。
3. 增强已有 inspectPage，固定提取 JSON-LD、Microdata、hreflang，禁止执行页面脚本。跨页和迁移分析基于实际证据文件，计算仍在现有 QuickJS 中。
4. 增加共享 Google 连接器（OAuth 授权、Search Console、Gmail），WordPress 应用密码连接器。采用官方 API，先生成可审阅草稿，再由现有审批框架授权发送/发布，持久化回执，未知结果不重试。
5. 增加浏览器本地定时监测，显式范围、频率和最多次数；使用 Chrome alarms，重启恢复，失败暂停，删除凭据后停止。保存可查询结果，浏览器关闭时不承诺运行。外联记录包括停止联系与跟进日期，不默认后台发送邮件。
6. 完成十八个自有技能与共享参考，按六类业务标签发现，集中配置依赖。公开包由同一源码导出，附许可、模拟样例、宿主工具合同与验证。
7. 运行类型检查、Lint、相关测试、构建与前端检查；使用独立 Git 工作目录/仅发布技能资产的提交发布公开仓库，避免带入混合工作区改动。

## 验收及边界

每个数据工具须保存接口、请求范围、时间、费用、分页/截断情况及固定版本证据。付费提交、发送和发布必须有实际审批与未知恢复保护。连接成功不等于每个 API 产品权限均可用。

代码及模拟服务测试可以本地完成；真实 Google OAuth 客户端注册、DataForSEO 各产品余额/权限、邮箱和 CMS 账户需要对应服务配置。本轮不虚构账户、不发送真实测试邮件、不用无凭据的结果宣称生产验收通过。

官方依据：docs.dataforseo.com/v3/on_page/task_post/、summary/、pages/、force_stop/；backlinks/domain_intersection/live/；developers.google.com/webmaster-tools/v1/；developers.google.com/workspace/gmail/api/guides/sending；developer.wordpress.org/rest-api/reference/posts/；developer.chrome.com/docs/extensions/reference/api/alarms。细节按实际实现逐项核对。
