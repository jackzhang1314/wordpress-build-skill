# 连接器设置流程与实现

日期：2026-09-07。基于同日官方对标研究，沿用现有设置页面组件和设计变量。

## 页面流程

| 起点 | 操作 | 下一页 | 返回行为 |
|---|---|---|---|
| 设置 | 点击连接器 | 连接器列表 | 返回设置 |
| 连接器列表 | 点击 Apify | 服务详情 | 返回连接器列表 |
| Apify 详情 | 连接 Apify / 管理授权配置 | 授权配置 | 返回详情并重新读取状态 |
| 授权配置 | 保存、测试、更换、删除 | 当前页面反馈 | 未保存草稿可取消离开；操作中阻止离开 |
| 技能管理详情 | 前往连接器配置 | Apify 详情 | 逐级返回后恢复原技能详情 |
| 对话的技能选择详情 | 前往连接器配置 | Apify 详情 | 逐级返回后恢复技能选择详情及任务草稿 |

## 本轮实现

- 设置新增独立「连接器」入口，和技能、模型连接并列。
- Connector 定义集中在 `src/agent/connections/catalog.ts`，目前只有 Apify；没有添加尚未实现的其他服务占位卡。
- 独立列表、详情与授权子页由 `connections/settings.ts` 管理；API 表单只出现在授权子页。
- 技能列表移除 Apify 表单；技能管理详情与选择详情使用统一依赖提示和配置跳转。
- 沿用已有 Apify 凭据键，不复制或删除已有 Token；页面不回填密钥。
- 区分未连接、已配置待验证、已验证、状态读取失败；服务详情单独说明采集工具尚未接入。
- 关联技能依据当前真实目录计算，不虚构已安装技能。

## 验证

TypeScript、ESLint、构建通过。设置导航、连接凭据、技能选择、技能管理共 34 项测试通过；新增覆盖已有凭据复用、返回技能详情不重建、未保存草稿拦截，以及从选择器返回仍保留任务草稿。

在 Codex 内置浏览器实际走过设置首页 → 连接器 → Apify → 授权配置，确认菜单、账户状态、关联技能空状态与表单均可见，截图检查无裁切。预览使用内存模拟存储；没有输入真实 Token。预览已保留在 `/all-settings?route=connectors`。Chrome 已安装扩展未代为重新加载。

## 边界

这是统一配置入口和交互的第一阶段。仍使用单个默认账户；尚未迁移为通用多账户 Connection 存储，也没有新增地图找客 Skill 或 Apify Actor 执行链路。不将账户验证描述为采集功能验收成功。当前没有使用真实 Apify Token 请求或启动付费采集。

下一阶段在连接器架构下建立任务绑定与实际工具调用，再交付地图找客 Skill；多账户存储扩展应独立验证凭据迁移和并发更新。
