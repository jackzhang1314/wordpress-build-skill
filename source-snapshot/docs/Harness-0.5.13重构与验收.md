# Harness 0.5.13 重构与验收

更新：2026-09-05 22:13 GMT+8。生产构建：`dist`，版本 0.5.13。

## 结论

本次问题主要位于应用对 AI SDK 的包装与上下文策略。继续采用已安装的 `ai@7.0.93` 的 `ToolLoopAgent`，没有更换内核或另建平行模型循环，也没有新增依赖。以下核心改动已经实现并验证；这不等于所有浏览器长任务都已稳定通过。

## 已补齐的机制

| 问题 | 实现 |
| --- | --- |
| 完整工具数据反复进入模型上下文 | 完整证据归档到 IndexedDB，模型接收有界预览与 contextRef；使用 readContext 分段回读，精确数据保存为文件并运行代码核验。 |
| 继续任务重新加载过大的历史 | ContextManager 经 prepareStep 统一整理工作副本，保存恢复检查点；pruneMessages 辅助维护工具调用配对。 |
| 压缩丢失当前指令的角色 | 保留结构化任务记忆，并将最新实际用户请求作为 user 消息保留；不把当前指令仅放入不可信历史材料。 |
| 摘要格式失败直接中断 | 使用 generateText + Output.object 和官方 Zod 类型；完整输出但不合规时最多纠正一次。截断、取消或仍失败时保留原历史，不把无效摘要提交为检查点。 |
| 仅以字符估算预算 | 纳入系统提示、工具 Schema、技能、消息及输出预留，并使用真实模型输入 token 校准估算；64K 工作预算不是供应商最大窗口声明。 |
| SDK 参数错误绕过应用记录 | onStepEnd 捕获 execute 之前的 tool-error；连续失败可见且会停止，成功结果重置计数。 |
| 工具包装丢失流式结果 | 包装器消费官方工具 AsyncIterable，保留进度及最终结果。 |
| 审批与 UI 调用 ID 脱节 | 使用官方 toolApproval，保存 approvalId/toolCallId；决定与开始执行分别先落盘，未知结果不自动重放，重复批准被拒绝。 |
| 超时后仍报告完成或继续写入 | SDK 分阶段 timeout 和 AbortSignal 贯穿运行器、网页及沙盒；不响应取消的工具停止等待，后续动作不再启动，迟到结果不能改成完成。 |
| 工具集和运行用量缺乏控制 | prepareStep 接入 activeTools/toolOrder，selectTools 按组切换；生命周期日志记录模型/工具时间、错误和 token/cache 用量，摘要请求也计费统计。日志只保留有界元数据。 |

默认仍不设总步数和任务总时长上限。首段输出、流片段和单次工具调用有独立超时；摘要也有单次请求超时。这些超时不会把正常第 20 步当成终点。

## 回归与边界

- 45 个测试文件、301 项测试通过；最终 typecheck、lint、build 通过。六种结果大小各 1,000 次调用的压力测试使用脚本模型，不能当作真实模型表现。
- 原生 Chrome 侧栏 + 官方适配器 + 原生 IndexedDB 的普通审批测试通过：批准前没有导航，批准后导航一次，重复批准被拒绝。该项供应商响应是确定性测试数据，见 [审批报告](Harness官方审批Chrome验收.json)。
- 后台恢复的运行器测试覆盖待批准恢复、拒绝恢复、未知结果不重放。原生 Chrome 后台重启自动化遇到 CDP 会话丢失，尚未完成，不计为通过；不能声称已经验证浏览器重启后的完整恢复。
- 本次真实模型验收使用生产沙盒引擎的独立 Worker，未覆盖 offscreen 消息传输。每阶段复用任务状态，未模拟整个浏览器重启。
- 合成数据任务证明这一组约束在三次压缩后仍能执行与核验，不代表 Alibaba 等真实站点的抓取完整率，也不保证任意摘要无损。真实网站、超长连续任务、不同模型及浏览器中断仍需继续验收。
- 没有实现无限内存；UI 历史与 SDK 步骤元数据仍可能随任务增长。未迁移 WorkflowAgent、Code Mode 或整套 UIMessage 协议，这些不是此次修复的前置条件。

## 本地使用

在 Chrome 的 `chrome://extensions` 中重新加载本项目插件，再关闭并重新打开侧栏。加载目录为本项目 `dist`。发布构建不含临时 harness-acceptance 页面；既有对话继续执行时会经过新的上下文准备流程，无需仅为旧字符限制另建对话。

测试入口源文件保留于 `tests/browser-harness-live.ts` 和 `scripts/build-harness-live.mjs`，仅在明确运行该脚本时生成临时验收页面。常规 `npm run build` 会清理它。

## 后续工具分组修复（H07，2026-09-08）

新增wordpress工具组，默认隐藏WordPress工具schema，模型先selectTools启用后才能调用。可组合files/skills/browser；切到其他组后释放WP schema。提问、交付核验及历史读取仍常驻，原五组兼容。此变更解决已知WP工具未分组而默认常驻的问题；未给所有未知工具自动分类，也不保证选择大量工具后预算必然足够。runtime既有activeTools与ContextManager预算保护保持。详见[H07记录](../process_docs/0908-22_Harness按需WordPress工具与预算隔离.md)；原页面历史成绩不属于新修复，H06业务失败仍未解除。
