# Skill 场景分类与使用交互优化建议

日期：2026-09-06。范围：Product Design 局部流程审查与源码架构评估，未修改产品代码。

## 证据与限制

本轮通过内置浏览器访问现有 /core-pages 预览，保存并回看三个截图。原生 Chrome 访问超时，不能视为真实插件验收。核心页预览的 agent:skills-list 明确返回空数组，空列表不代表产品没有内置技能。另一设置预览进入了网页助手页，与预期技能路由不符，其截图不作为技能审查证据。技能详情、选择后状态、真实导入和完整键盘流程未完成现场验证；相关判断以下明确来自源码。

| 步骤 | 状态 | 发现 |
|---|---|---|
| 1. 从对话寻找技能入口 | 可用，发现性待改善 | 输入区图标有“使用技能”无障碍名称，但没有常显文字，新用户需探索 |
| 2. 打开选择技能 | 导航可用；预览数据阻塞 | 返回清晰，搜索有标签；无数据时只显示“没有匹配的技能”，没有区分未安装、搜索无结果和加载错误 |

## 分类方案

以任务场景为一级分类，以岗位、平台和页面类型为交叉标签。避免用户必须在“业务员”和“运营”之间选择唯一身份。

| 主分类 | 典型技能 |
|---|---|
| 找客户与背调 | Google 找客、地图商家、相似客户、官网背调、联系人定位 |
| 客户沟通 | 开发信、询盘回复、跟进草稿、商务翻译 |
| 建站与页面优化 | 网站规划、B2B 文案、同行结构、询盘转化检查 |
| SEO 优化 | On-page SEO、搜索意图、内容缺口、内链、多语言、GSC 分析 |
| 社媒推广 | 产品转帖子、案例复用、内容日历、评论/私信草稿 |
| 广告投放 | 搜索词、否词、广告文案、落地页一致性、报表复盘 |
| 数据与资料整理 | 网页转表格、商品对比、文件清洗、批注交接 |

阿里国际站、Google Maps、LinkedIn 等使用平台标签；“阿里运营包”“业务员入门包”是精选集合，引用已有技能，不复制技能正文。每项有一个主要归属，可有多个标签和合集。分类无可用技能时不制造空入口；未实现的目录项不能显示为可执行。

## 使用交互

日常入口保留在输入框，用“技能”文字加图标。打开轻量选择器，默认展示当前页面相关、最近使用和收藏；“全部场景”进入分类页。不要为七个分类在窄侧栏横排七个标签，可用分类选择及列表。

列表每项只展示中文任务名、一句话交付结果、是否需要资料/连接及主要动作。例：“On-page SEO 检查：检查当前页面，交付可定位的修改清单”。点击后显示简短任务配置：当前页自动带入，关键词与市场可选，产品资料可复用；不重复询问对话已知内容。

配置完成在输入框显示可移除的技能标签，并允许补充说明。显式点击“开始检查”或发送后执行，选择技能本身不自动发送请求。保留 / 指令作为熟练用户快捷方式，模板用于填写任务输入，Skill 用于任务方法，两者在界面上解释清楚。

详情先展示用途、需要的资料、结果样例、支持范围和执行条件；工作方法、来源、版本、许可及原文放在展开区。当前可用技能与需要连接器的候选不能混为“已安装即可运行”。

管理入口放在技能页次级入口及设置中，负责导入、启用、更新、版本和删除。普通选择页不直接放启用开关；不可用时给出原因和去管理/补资料的动作。

完成后给任务相应的下一步：客户卡→写信/找相似；SEO→查看位置/保存批注/导出/复查；搜索词→更正分类/导出候选。这里包含待开发的专属结果操作，不是当前能力声明。

## 架构调整

| 层级 | 职责 |
|---|---|
| 分类与精选集合 | 负责发现；场景、岗位、平台、收藏和排序 |
| 技能产品目录 | 稳定 ID、中文标题、别名、主要分类、标签、输入、输出、依赖、验证状态及来源 |
| Skill 方法包 | SKILL.md、references 和样例，定义步骤与事实核验 |
| 任务编排 | 选择资料、校验依赖、按步骤加载、保留版本与执行状态 |
| 共享工具与成果 | 网页、视觉、文件、计算、批注和后续连接器；保存可追溯成果 |

建议产品目录作为 SKILL.md 的配套元数据，保留现有原包导入兼容。没有分类的外部技能进入“我的导入/待分类”，允许用户修改分类；推断的标签可编辑，不直接相信上游声明的兼容性或验证状态。

安装一个岗位包只添加技能集合，不等于激活全部。保留当前有界加载，后续增加安全的阶段切换：当前约束与已做决定保留，已完成技能可退出活动上下文，历史版本仍可追溯；不能简单卸载技能导致事实核验规则或待执行步骤丢失。此为后续工程设计，不能用分类改动暗中替换现有运行机制。

## 实施建议

1. 先确定分类、技能卡信息和目录字段，映射现有 8 个内置技能，不改运行内核。
2. 改日常选择器与管理入口；以 On-page SEO 验证“发现→配置→运行→成果→复查”流程。
3. 再扩充外贸技能包、依赖检测与阶段加载；以真实任务验证开始耗时、错选率、输入补充次数、成果采用和复用。

后续视觉设计应以当前侧栏截图为依据，先形成选择器、技能详情/配置和管理页方案，再进入代码实现。
