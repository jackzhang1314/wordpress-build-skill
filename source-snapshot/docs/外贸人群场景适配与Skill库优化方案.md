# 外贸人群场景适配与 Skill 库优化方案

日期：2026-09-06。基线：本项目 v0.5.14 当前源码。范围：产品研究与候选整理；未安装第三方技能、修改产品代码或连接业务账号。以下优先级是产品假设，尚未经用户访谈验证。

## 1. 产品方向

让用户在客户官网、独立站、社媒和广告报表之间持续使用同一份企业资料，完成找客、判断、内容准备、优化与成果交付。建议以岗位组织推荐包，以当前页面和用户任务选择技能，不把岗位变成互斥模式。

| 用户 | 首要适配场景 | 交付物 | 当前可复用 | 待补充 |
|---|---|---|---|---|
| 外贸独立站建站人员 | 竞品结构研究、建站资料整理、产品页采购信息检查、上线前检查 | 页面清单、文案、字段缺口、定位批注、交接包 | 网站结构 Skill、页面检查、视觉输入、批注创建和文件交付 | B2B 页面模板、CMS 字段映射、修改后复查；完整源码构建部署需独立环境 |
| 独立站运营/SEO | 当前页 SEO、关键词与页面匹配、内容缺口、多语言参数一致性 | 原值与建议值、关键词页面表、内容计划 | technical-seo、表格文件读取、脚本计算 | GSC CSV 适配、语言版本关联、修改历史 |
| 外贸业务员 | 搜索找客、相似客户、官网背调、联系人定位、个性化开发信 | 有来源客户表、客户卡、匹配产品、邮件草稿 | company-research、浏览器任务、列表采集、文件库 | 跨任务客户实体、域名去重、联系状态；邮件服务另接 |
| 阿里国际站运营 | 商品研究、产品信息检查、RFQ 匹配、报表分析 | 商品对比表、缺项清单、RFQ 候选和回复草稿 | alibaba-research 和列表提取 | RFQ/卖家产品编辑页分别适配和验收；商品采集不能代表卖家运营已完成 |
| 外贸社媒运营 | 产品/案例转多平台内容、同行公开内容研究、评论与私信草稿、内容日历 | 平台版本、配图说明、视频脚本、来源、行动号召、日历表 | 网页读取、视觉输入、文件与提示词 | 品牌语气、内容素材关联、平台编辑器、发布状态；图片视频生成及定时发布需要额外工具 |
| Google/Meta/LinkedIn 投手 | 搜索词与否词、广告落地页一致性、广告文案、公开竞品素材研究 | 分类表、否词候选、批注、广告草稿和实验计划 | search-term-review、代码计算、视觉与批注 | 报表字段映射、业务保护规则、有效询盘口径；账户直连后置 |

## 4. Skill 库加载优化

1. 提供五个可叠加推荐包：业务开发、独立站建站与转化、SEO 运营、社媒推广、广告投放。阿里专项作为平台补充。
2. 每个技能展示中文任务名、输入示例、输出样例、支持的平台、依赖条件、验证状态和来源版本。区分“可直接使用”“需要资料”“需要连接服务”。
3. 公司官网推荐背调/联系人/产品匹配，自己网站推荐 SEO/询盘诊断，报表推荐搜索词分析，社媒页面推荐研究/改写/互动草稿。用户可纠正页面角色。
4. 安装与激活分开。目前运行时最多同时激活 4 个技能、正文总量 24,000 字符。建议按任务阶段选择有限技能，并按需读取 references；不把整个岗位包同时塞进上下文。
5. 上游导入先做路径、正文、引用、依赖检查，再固定提交并测试。更新显示差异，保留用户修改版；失败不能显示“已可用”。
6. `npx skills add` 装到开发电脑，与 Chrome 插件内置/用户导入是不同动作。正式分发要写入项目技能注册或发布插件可导入的 ZIP。

## 5. 比增加技能数量更重要的功能

| 功能定制 | 具体增量 | 用户价值 |
|---|---|---|
| 企业与产品资料 | 在已有职业/背景/偏好和资料收藏上增加产品事实、目标市场、术语、可公开卖点、更新时间、多企业选择 | 背调、社媒、广告、文案共用准确资料，少重复输入 |
| 场景结果卡 | 客户卡可保存/找相似/写信；诊断卡可批注/导出/复查；社媒卡可切换平台版本；搜索词卡可改分类/导出否词 | 用户能直接采用结果 |
| 内容来源复用 | 把产品页、案例、图片与内容草稿关联，生成 LinkedIn/Facebook/Instagram 等版本，保留原文证据 | 一份真实素材支持多个推广渠道 |
| 平台适配 | 先选实际高频平台，覆盖页面识别、当前编辑对象、字段填写、分页、结果回读和失效提示 | 减少通用点击试错；不同页面分别验收 |
| 轻量客户档案 | 按公司域名/主体保存，关联联系人、来源、匹配产品、草稿及开发状态 | 找到的客户可跨任务继续使用 |
| 广告报表工作台 | 导入后识别日期、币种、字段、转化定义；分类可更正，否词检查业务误伤 | 形成可对账、可导入的优化清单 |
| 采纳与偏好复用 | 用户明确选择“记住此规则”，记录品牌语气、排除客户、可接受文案和术语 | 下次任务更符合企业习惯 |
| 任务成本反馈 | 执行前显示范围与估算，过程中显示实际用量、已完成和缺口 | 批量找客/图片任务费用更可控 |

当前已存在 createAnnotation，不应继续把“Agent 创建批注”列为从零开发。已有个人业务背景也不等于结构化、多企业产品档案。应在现有能力上增量实现。

## 6. 建议实施顺序

- 第一批：适配询盘转化、B2B 文案、社媒内容三个新技能；将 SEO 专业包中的 On-page SEO 检查列为重点，增强现有 technical-seo、公司研究和搜索词技能；配套企业资料选择、来源引用和结果继续操作。
- 第二批：客户清单与跨任务去重、社媒内容日历、否词表、GSC CSV、一个明确 CMS/社媒编辑器适配。
- 第三批：邮箱、GSC、Google Ads 与社媒连接器；确有需求后接后台定时任务。完整建站部署接开发执行环境。

第一批建议用业务员、独立站运营、社媒运营、投手的真实任务分别验证。观察完成时间、事实错误、修改次数、导出/采用率和一周内再次使用；不拿生成字数或技能数量代替价值，也不在无业务数据时承诺询盘增长。

如果“积分的定制”确指积分计费：先区分用户自带 Key 与平台代付模型。自带 Key 已产生模型费用，产品订阅应明确对应资料、协作和专业流程；代付模式再考虑积分，执行前展示估算和上限，区分失败的实际服务成本与成果交付，避免不透明扣费。目前不建议以积分系统作为场景适配第一优先级。

## 7. SEO 专业技能包：重点加入 On-page SEO

用户补充：SEO 相关场景单独成包，重点包含 On-page SEO 检查。以下为待适配范围，不代表已经安装或实现。

| 场景 | 输入 | 检查或分析范围 | 交付物 |
|---|---|---|---|
| On-page SEO 检查（重点） | 当前页面、目标关键词、语言、国家与页面用途 | 标题与描述是否准确表达内容；H1/H2 与正文结构；采购意图与页面内容匹配；产品规格、应用、选型问题覆盖；图片 alt、内链与锚文本 | 原值、证据、问题、建议值和优先级，可定位为批注 |
| 页面技术基础检查 | 当前页面及可取得的技术证据 | canonical、页面 robots、语言与结构化数据；区分 DOM 观察和需要额外验证的响应/索引信息 | 技术问题表、已验证和待验证项 |
| 关键词与承接页面规划 | 产品资料、目标词、实际搜索样本 | 判断由产品页、分类页、应用页、选型指南或文章承接；发现错配与覆盖缺口 | 关键词到页面的映射表 |
| 搜索结果与同行内容研究 | 关键词、市场和指定样本 | 访问实际结果，比较页面类型、采购信息与可补充内容 | 样本对照、页面提纲与需补资料 |
| 内链与网站结构 | 已访问页面或用户提供的 URL 清单 | 产品、分类、应用和文章之间的关系；链接与锚文本改进 | 内链建议、页面关系和覆盖范围 |
| 多语言页面检查 | 对应语言版本、术语和产品事实 | 术语、型号、单位一致性；可取得的 hreflang/canonical 对应关系 | 版本差异和修改清单 |
| 搜索表现与内容更新 | GSC 导出、可比日期、国家/设备及页面 | 有曝光低点击、查询页面匹配、变化位置，结合排名及样本判断 | 优先复查页面与建议动作；不凭页面猜流量 |
| 修改后复查 | 原报告、批注及修改后的页面 | 重新读取字段和内容，逐项核对是否落实，区分已改与未验证 | 修改前后对照及剩余问题 |

首个用户入口建议为“检查这页的 SEO”：网址默认取当前页，目标关键词与市场可选填；缺少关键词时先做基础检查。结果提供“查看位置、采用改稿、保存批注、导出修改清单、修改后复查”。发布到网站需要相应 CMS 或开发工作流，保存本地建议不算已上线。

实现上复用 technical-seo、inspectPage、文件工作区和 createAnnotation；新增内容意图、采购信息和页面文案的检查方法。图片、结构化数据、语言映射等字段需要检查实际工具覆盖后补充，不能仅靠技能描述宣称可读。上游 seo-audit、copywriting、site-architecture 作为候选参考，按任务加载，不重复内置整套技能。
