# 原生站点设置与导航适配方案

2026-09-08。先研究后实施，基线f750d05。

1. 原生 /wp/v2/settings 已支持title/description/show_on_front/page_on_front/page_for_posts。复用wpReadSite、wpConfigureSite，增加source=native|companion；保留旧默认companion兼容已安装Skill，当前Skill显式优先native。不自动回退到另一写接口。
2. 原生设置只暴露上述五项，读取其有界状态计算带连接身份的revision。更新前重读并核对revision；首页/文章页必须是已发布page且不能相同。写后回读逐项核验。原生revision是客户端变化检测，不具备服务端原子条件写，需明确剩余竞态。
3. 配套插件仍保留已有服务端revision冲突机制，仅用于需要它的站点。原生设置不要求安装插件。
4. wpRead增加navigation/templates/templateParts只读分页，schema与完整内容进入任务证据。先确认实际主题引用；导航草稿不等于已绑定页眉。当前阶段不开放任意模板HTML写入或主题安装。后续以保留原布局、精确目标和版本核对为前提适配导航/模板修改。
5. 验证设置映射、参数拒绝、旧revision/草稿阻止写、写后回读、未知不重发；无插件WordPress隔离站验证官方settings与列表接口。

官方来源：https://developer.wordpress.org/rest-api/reference/settings/ 。导航/模板接口以实际WordPress REST discovery和OPTIONS核对，不因文档URL打开失败推断不支持。

实施研究补充：官方模板列表无page/per_page参数，templates/templateParts使用受连接器响应大小限制的集合读取后本地ID排序分页；navigation仍为服务端分页。官方文档：https://developer.wordpress.org/rest-api/reference/wp_templates/ 、https://developer.wordpress.org/rest-api/reference/wp_template_parts/ 、https://developer.wordpress.org/rest-api/reference/wp_navigations/ 。
