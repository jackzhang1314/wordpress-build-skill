# 从规划开始落实搜索质量

用于新站 Discover、内容规划、页面设计和发布评审。技术实现见 [seo.md](seo.md)，页面类型见 [b2b-pages.md](b2b-pages.md)。本规范将官方原则转换为本项目建站约定，不是 Google 评分表或排名保证。资料核对：2026-09-20。

## 来源与使用边界

| 一手来源 | 在本方案中的用途 |
| --- | --- |
| [Google Search Essentials](https://developers.google.com/search/docs/essentials) | 技术资格、垃圾内容政策与关键实践的总入口 |
| [SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) | 站点组织、内容、标题、链接和常见误区 |
| [Helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) | 核对内容是否有价值、可信、说明谁负责与如何产生 |
| [Search Quality Rater Guidelines 官方概览 PDF](https://services.google.com/fh/files/misc/hsw-sqrg.pdf) | 借鉴页面目的、主内容质量、声誉与需求满足的评审视角，尤其第 18–30 页 |
| [Spam policies](https://developers.google.com/search/docs/essentials/spam-policies) | 排除门页、关键词堆砌、链接操纵和无价值规模化内容 |
| [Page experience](https://developers.google.com/search/docs/appearance/page-experience) | 兼顾移动可用性、HTTPS、主要内容可达性和性能，不能只追求工具满分 |

质量评估员的评分不直接决定单页排名，E-E-A-T 也不是一个可填写或由插件计算的独立排名分数。将它用于审查真实证据和用户帮助程度，不造“E-E-A-T 达标证书”。完整评估员指南 PDF 本轮抓取失败，已阅读 Google 官方概览与当前 Search Central 的解释；不声称逐条审阅了完整版最新修订。

WordPress 的[SEO 文档](https://wordpress.org/documentation/article/search-engine-optimization/)可作机制入口，但仍包含旧式目录提交和文章数量建议，不作为当前 Google 要求。搜索规则以 Google 当前一手资料为准，具体配置以目标 WordPress 版本和实际输出为准。

## 开工前：每类页面的内容契约

在已有 Brief/站点地图中记录下列项目，不强制额外创建一套同义文档；信息可从已有资料推导，缺业务事实允许以明确 mock 推进预览。

| 项目 | 必须回答的问题 |
| --- | --- |
| 买家与市场 | 谁会访问、语言是什么、处于了解/比较/验证/询价哪一阶段？ |
| 页面目的 | 用户来到这一页要解决什么问题，完成后去哪里？ |
| 查询与表达 | 买家如何描述需求？主要概念及自然同义表达是什么？没有数据时不伪造搜索量或竞争度 |
| 独立价值 | 相比已有分类/产品/方案页，这一页新增什么信息？没有增量则合并，不按关键词机械分裂页面 |
| 内容与证据 | 需要哪些参数、照片、测试记录、认证/文件？各自来源和核验状态是什么？ |
| 责任与更新 | 由哪个真实企业/团队/作者提供，谁审校，哪些变化触发更新？ |
| URL 与关联 | 页面类型、稳定 URL、索引策略、上级入口、相关产品/方案和主 CTA |

该契约属于规划与评审输入，不是新增 content-plan/project-init CLI 字段；不得向现有严格 schema 塞入未支持属性。

## 将可信度做进内容模型

- 企业身份、业务角色、服务范围与联系渠道明确一致；About、联系方式及适用的服务/隐私说明容易找到。制造商、贸易商和代理商按事实表达，不能以模板默认文案冒充制造能力。
- 事实、计算结果、示例和营销判断分开。关键参数记录来源/单位/适用型号；案例记录条件、实施过程与可核验结果。需要时在项目模型中设计来源与审校信息，不要求每个营销字段都有冗长脚注。
- 真实工厂/产品照片、试验资料和专业解答优先；AI 图片或 mock 不当作客户、工厂、认证或项目成功证据。用户未提供资料仍可完成原型，正式发布前替换、删除或如实标明未证实内容。
- 作者或技术审校者按内容需要展示真实身份和经验；不为所有产品页机械编造“专家作者”。涉及设备安全、操作或重大采购判断的技术建议，应由具备实际知识的责任人核对，未核实内容不写成操作保证。
- 引用可信外部资料时保留来源；既无证据也无授权的客户 logo、认证、评分、销量不进入真实发布。声誉不能靠虚构客户评价或批量购买链接替代。

以上是面向本项目的内容治理设计；Google 没有要求每站固定数量的作者、案例或证书。

## 页面质量与需求满足评审

同一产品参数可以被多套模板读取，但不同页面要完成不同任务：分类帮助选型，详情解释适用条件与规格，方案解释工况与取舍，About 证明企业身份，联系页让采购方完成真实询盘。

发布前逐页回答：

1. 主要内容是否直接完成页面目的，而不是只剩漂亮横幅和通用宣传？
2. 采购者能否找到关键差异、限制、兼容条件及下一步行动？资料不足是否如实处理？
3. 文字是否有独立帮助，能否说明经验或依据，而不是重写同行页面、同义词扩写或型号替换？
4. 页面标题是否准确描述内容？关键词自然出现在相关位置，不堆砌在正文、alt 或链接中。
5. 联系方式、文件下载、询盘和导航是否可用？弹窗、浮动按钮和动画是否遮挡主要内容，移动端是否同样完整？
6. 内容责任与适用范围是否清楚，更新是否基于实质变更，而不是只改发布日期？

不设 Google 未规定的“最低字数”“关键词密度”“至少十篇文章”门槛；SEO 插件绿灯、单个 H1 或 Lighthouse 满分均不能替代上述评审。主标题和语义层级依然作为本项目可读性/结构规范，不能冒充 Google 的硬性排名公式。

## Codex 生成与批量建页

AI 可以用于整理资料、生成布局、辅助写作和校验。每轮先验证少量代表页面的价值与事实，再批量扩展；不设固定数量门槛。

不得批量制作只改城市/国家/关键词的门页，不把抓取或改写内容当作原创证据，不使用隐藏关键词、链接交易或自动评论推广。判断规模化内容看其目的与价值，不以“人工写的”自动豁免，也不因“AI 写的”自动否定。确有当地服务或独立应用资料时可建设对应页面，明确差异证据。AI 使用说明在读者合理需要了解制作方式时提供，不机械在每页加同一声明。

## 交付与持续维护

将质量评审和 [SEO 技术检查](seo.md) 并入现有阶段证据：记录页面/版本、检查结果、证据位置和未覆盖项。事实来源不成立、主要内容不满足承诺或误导用户时修正后再作真实交付；mock 预览保持预览身份。

公开上线后，在授权范围内检查 Search Console 的抓取/索引、查询与页面表现，结合真实询盘质量优化内容；不只统计页面数量和曝光。新增产品、参数变化、资料失效、链接失效和模板更新触发相关复核。监控若需自动定时运行，另按用户明确的自动化请求设置，不因本规范自动创建任务。
