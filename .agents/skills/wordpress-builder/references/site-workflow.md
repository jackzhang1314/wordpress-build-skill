# 新站交付工作流

B2B 外贸站先用 [逐页实施策略](b2b-pages.md) 建立页面与内容模型映射。

仅用于整站任务；本方案建成站点的局部修改按实际影响验证，不重走所有阶段。

1. **Discover**：按 [搜索质量](search-quality.md) 把买家/市场、页面目的、查询意图、独立价值和事实来源写入已有 Brief/站点地图；按 [项目指令规范](project-instructions.md) 建立或合并客户 AGENTS.md，核对真实路径与命令；初始化契约，官方本地 triage 与实际 WordPress 环境探测互补。确认干净站、权限、实际版本、ACF 版本与用户授权。目标主机不明确不阻塞本地开发，但不能宣称生产兼容。
2. **Model**：官方插件/REST 工作流 + 项目 ACF 规则；同步定义 URL/索引矩阵、内容来源与真实责任信息，区分公开产品和内部询盘。定义产品/案例/分类、编辑字段与图片关系，记录 schema、权限和数据来源；验证一个产品与一个分类能编辑保存。
3. **Theme**：按统一架构组合区块主题、原生模板/Patterns、CPT/ACF 和必要 PHP 动态模块，先实现代表性页面再扩展；独立 PHP 整页例外单独记录路由和编辑范围。设计按需预览，最终验收实际 WordPress。主题消费同一内容模型，不重新命名字段。
4. **Content**：读取完整企业资料，媒体上传后按实际 ID 写入内容，补导航和内部链接；缺失事实保留待补标记，不编造。核对页面价值、关键事实/图片、内容责任、标题与描述；表单和 SEO 配置在此确认。
5. **Verify**：汇总专业检查，补后台编辑、前台路由、移动端、询盘和恢复的跨模块检查；按 [seo.md](seo.md) 验证原始 HTML、链接、分页/筛选、索引策略和真实性。同时逐页核对目的是否达成、信息是否可信、是否满足买家需求。API 成功与手写 pass 不能替代证据。
6. **Release**：记录代码/数据库/媒体版本，按目标环境发布并回读。区块 build 发布门禁与文件部署分别验证，说明各自覆盖边界。交付网站、编辑方法、依赖与未覆盖项。

专业模块交接格式与阶段记录见 orchestration.md/runtime.md。阶段检查只是可追踪声明，不自动改变 WordPress 发布状态。实际部署和数据写入仍使用对应工具及既有授权。

新站产物应独立于 TerraLift 示例：行业字段、企业素材与文案属于项目，工具不固化行业假设。第二个行业从空环境验证通用性，不能复制旧演示数据库后宣称全新建站成功。


## 各阶段最低质量产物

并入现有项目文档/回执，不建立第二套重复状态系统：

| 阶段 | 产物与完成条件 |
| --- | --- |
| Discover | 页面任务/独立价值/来源清单；未知事实标记，mock 与正式内容分开 |
| Model / Theme | URL 与索引矩阵；字段/模板/SEO 输出责任；代表页核心 HTML、链接、移动交互可用 |
| Content | 关键事实核验、真实责任信息、页面差异和主 CTA；无虚构信任证据、门页或堆砌关键词 |
| Verify / Release | 技术 SEO 与内容质量的逐页证据；预览/生产可见性正确；未测项不写 pass |

公开上线后的 Search Console、真实 CWV 和询盘表现另留适用环境证据；这不是自动化调度请求。以上为 Skill 的流程要求，当前 CLI release schema 并未自动执行或强制验证全部 SEO/内容质量项。
