# 企业资料到真实网站

先确定采购者需要完成的动作和企业已有事实，设计首页、产品、关于、联系及任务要求的其他页面。四页是标准起点，不是全部任务的完成定义。不要把示例企业资料用于客户生产站。

记录企业资料路径、产品参数来源、图片来源、语言、询盘入口和缺失项。当前工具只检查 sourceFiles 字段结构，资料真实性由 Codex 实际读取核验；不能把字段存在当事实审查通过。

设计前读取实际主题与模板。颜色、排版、留白、内容宽度要在现有主题下检查；注册区块存在不代表任意设计属性可用。先完成一页视觉验证，再批量扩展。原生页面标题由主题处理，正文从 H2 开始；最终以实际 H1 数量为准。

草稿创建时暂省略尚未有实际目标的内部按钮；全部 ID 返回后工具自动补齐。draft 阶段完成时必须看到最终互链，临时内容不可进入验收。重新执行必须复用原计划与目录，不会以新页面代替已保存进度。

在浏览器确认登录到对应站点，读取编辑器的实际区块状态，检查是否存在无效块。预览覆盖桌面和手机；保存截图并实际查看。检查标题、文本层级、图片比例、按钮对比度、页面宽度及跳转目标。对无法验证的项目如实记录。

发布保留正文，发布后重新检查前台链接和导航。导航计划不改主题、页脚或部件内其他内容。页脚、全局样式、业务表单、产品动态字段如属用户要求，仍需单独完成，不能因为四页发布而忽略。

交付报告逐项区分：已完成、有证据但有兼容限制、待实现、待用户资料。记录实际主题与 WordPress 版本；CLI 的请求版本参数不是实际安装版本证据。
