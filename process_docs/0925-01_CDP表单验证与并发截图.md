# 0925-01 CDP 表单验证与并发截图

- 时间：2026-09-25 00:50 Asia/Shanghai
- 触发原因：真实表单验证仍是手工流程；全量截图逐次启动 Chrome 导致 69 张截图过慢。
- 技术决策：
  - 不引入 Playwright / Puppeteer。
  - 使用 Node 22 全局 WebSocket + Chrome DevTools Protocol。
  - 一个 headless Chrome 进程可复用多个 CDP page，并发完成截图。
  - 表单验证复用同一浏览器层，能真实导航、填字段、点击提交并等待成功提示。
- 新增能力：
  - `harness/lib/cdp-browser.mjs`：CdpPage、CdpBrowser、launchCdpBrowser、bounded concurrency。
  - `screenshot --mode smoke|templates|full`、`--routes`、`--concurrency`。
  - 项目配置 `screenshotModes.smoke / templates / full`。
  - `verify --screenshots --mode ...`。
  - `verify-form`：HTML 渲染、浏览器提交、Fluent Forms entry 增量、最新 entry 状态三重验证。
- 验证：
  - smoke 截图 15/15 成功，CDP 共享浏览器耗时约 9.5 秒。
  - live `verify-form` 15/15 成功；entry 由 1 增至 2，最新 entry status `unread`。
  - 本地 typecheck、lint、144/144 tests、starter harness check 全绿。
- 经验：
  - Chrome CLI 不需要每个截图单独启动浏览器；CDP page 可复用。
  - 全量截图用于发布验收；模板级截图用于 UI 审计；smoke 用于日常改动。
  - CDP 的 Node WebSocket 需等待 `open` 后再发送请求。
  - 表单验证必须在浏览器页面里导航，不能只用 fetch HTML 后假设 page 已到达目标路由。
