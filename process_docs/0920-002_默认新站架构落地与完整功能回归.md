## 触发与决策

用户要求继续落实和重构，收敛可交付方案。对当前自由 HTML + ACF + 原生正文的新站需求，默认采用 PHP 混合主题与独立业务插件；区块主题保留给整站可视化编辑需求。此决策依据需求匹配与本地功能实测，不声称完成两条路线的性能/成本对照。

## 实现

- Skill 随包提供 [PHP 参考源码](../.agents/skills/wordpress-builder/assets/php-reference/)，包含首页、产品、分类、普通页、文章、归档、搜索、404、theme.json 与独立 CPT/ACF 插件。主题不注册业务模型，插件不预置演示数据、不实现自有表单引擎。
- [独立启动脚本](../scripts/reference-site.mjs) 在全新数据库部署参考站，复用实际安装的 ACF、Fluent Forms、The SEO Framework 插件文件；未复制旧演示数据库。显式 loopback 9463，检查端口占用，Blueprint 使用实际安装版本的官方 schema 校验。
- 按官方插件/Playground/Blueprint Skill 执行工作流，实际运行官方项目识别和插件扫描。初始演示内容与本地邮件捕获仅在测试脚本中，不混入可分发主题/业务插件。
- 修复初始 permalink 设置顺序：只 update_option 后 flush 会用旧重写对象，未知路径错误跳首页；改为 wp_rewrite->set_permalink_structure 后重新建库验证 404。
- 导航改为 WordPress 对象菜单项，询盘入口存页面 ID，通过 permalink 生成 URL；联系页改 slug 后导航与 CTA 不失效。
- 同步 README、架构、Skill 入口、模块交接和参考站说明。明确研究库、可执行模块、功能参考站与生产交付的区别。
