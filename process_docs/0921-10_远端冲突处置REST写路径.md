时间：2026-09-22 00:40 +08:00（Asia/Shanghai）。
触发：0921-09 远端只读预检闭环后，用户确认按 B 方案（REST 写通道）接入远端处置。

## 主要工作

- 抽取 `scripts/hostinger/rest-session.mjs`：testcookie 登录、admin-ajax rest-nonce、cookie+nonce 请求；nonce 过期 403 自动重登一次；连接阶段瞬态错误（UND_ERR_CONNECT_TIMEOUT/ECONNREFUSED）任何方法可安全重试，读错误（ECONNRESET 等）仅 GET 重试，已发出请求的失败按结果未知不盲重。`remote-preflight.mjs` 重构复用，回归通过（0 变更/0 覆盖/0 冲突与首轮一致）。
- 新增 `scripts/hostinger/remote-resolve.mjs`（npm run hostinger:remote-resolve）：远端 reset/restore。reset：REST 盘点锁定 source=custom+publish 覆盖 → 备份写本地私有目录并读回校验 → 逐条 force 删除 → previous 哈希核对 → GET 404 三重确认；任一路径无覆盖整批拒绝；theme.json 拒处置。restore：备份域名校验 + validateBackupShape → id 不存在前置 → POST 重建（parts 回填 area）→ GET 哈希核对。备份带 domain，跨站恢复拒绝。
- 演练 `scripts/hostinger/remote-resolve-check.mjs`（npm run test:hostinger:remote-resolve）：线上唯一 `harness-rresolve-*` 夹具 → POST 创建 → reset 备份+删除+404 → restore 重建哈希一致 → 负路径整批拒绝 → finally 清零。三轮通过（加固后连续两次），站点最终零夹具、零临时目录。证据 `docs/acceptance/template-update/hostinger-resolve.json`。

## 实际失败与修复（全保留）

1. 第一次演练在清理验证 GET 处 connect timeout 崩溃：DELETE 实际已成功（事后查证零残留），但脚本未跑到断言、证据未落盘。根因是会话层无重试且「清理路径」与主流程共用无保护请求。修复：会话层按错误类别重试（连接未建立=安全；已发出=结果未知不盲重），演练清理与 CLI 共用该会话。
2. 第二次演练在 reset/restore 中途 socket 错误（bytesWritten>0，请求已发出）崩溃，夹具短暂残留（publish 状态）；按「结果未知先查证」用 REST 盘点确认归属后手动按 id 删除，与重跑夹具（相邻时间戳、仅三个字母之差）仔细区分，避免误删本轮夹具。
3. lint 三处：未用 `privateDir` 变量、`slug`/`contentHash` 无效初始赋值——同款问题第三次出现，模式已写入 verification.md。
