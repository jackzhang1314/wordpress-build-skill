# 标题层级关卡与首次真实增量发布

时间：2026-09-22 01:29 +08:00（Asia/Shanghai）。
触发：本地与远端增量链路闭环后，用户确认做首次真实增量发布。用户先要求架构级方案而非点修复，遂先研究再实现。

## 研究结论

- WordPress 官方 Twenty Twenty-Five：查询循环 `wp:post-title` 不带 level（默认渲染 **h2**）跟随页面 h1；单页模板显式 `{"level":1}`。本主题 6 个列表模板硬编码 level 3 属偏离惯例。
- axe-core `heading-order` / Lighthouse「标题顺序递减」为标准无障碍检查项；h1→h3 跳级会被标记。
- harness 现状：只有 h1 数量检查，无标题顺序关卡——系统性缺口，点修复无法防复发。

## 主要工作

1. **新关卡**：`heading-lint.mjs`（npm run test:starter:headings）静态组装模板（解析 template-part/pattern 引用、剥 PHP、循环安全、核心块默认级别：heading/post-title 2、query-title/site-title 1）→ 文档序判定升幅>1 即违规。修复过程中发现并修正块名正则不含连字符的重大解析缺陷（曾致 query-title/post-title 全部漏检，假阴性 0 违规）。3 项离线夹具测试（组装+跳级、默认级别+同/降级通过、模式引用缺失报错）。
2. **渲染门**：既有 design-check/浏览器审计覆盖视觉与 h1 数量，本次层级由静态关卡+线上实测双重验证。
3. **修复**：lint 输出权威违规清单 6 个模板（archive-hd_product/archive-hd_solution/home/index/search/taxonomy-hd_category），各改 `post-title level:3→2`。CSS 全部为块类选择器显式字号（.catalogue-grid/.guide-directory 等），视觉零变化；前端验证 h1 数量与布局不变。
4. **增量传输关卡**：`incremental-deploy.mjs`——预检冲突门（blocked 即退 2）→ 变更文件远端备份至私有目录 → generate-upload-url + TUS（POST 201/PATCH 204）上传 → website-content 读回哈希核对（归一化 LF）→ `cache clear-website`（位置参数 user domain）→ 复检收敛（变更归零）。二进制/删除类变更明确拒绝。
5. **真实发布**：6 文件上传、读回一致、缓存清、收敛 0 变更；线上 /blog/、/?s=excavator、/industry/ 层级 0 跳级（文章/结果/行业标题现为 h2），/ 与 /equipment/ 无回归。证据 `docs/acceptance/template-update/hostinger-incremental-release.json`。

## 实际失败与修复（全保留）

1. **基线工具 LF 归一化设计缺陷（重要）**：首跑发布崩溃——归一化兜底断言隐含「远端≈候选」，候选真有变更时（基线工具本职场景）必崩。此缺陷在远端=候选时代潜伏，真实变更首日即暴露。修正为对称语义：远端哈希按剥 LF 字节记录并标记；派生层候选剥 LF/补 LF 与远端一致均判未变（字节精确、不掩盖真变更），补 2 条测试。
2. **块名正则漏连字符（重要）**：heading-lint 初版 `[a-z0-9]+` 不匹配 query-title/post-title/template-part，假阴性 0 违规；本地 reuse 站内容极简（0 文章）曾使渲染验证信号过弱，靠单元夹具与真站对照发现。修正 `[a-z0-9-]+`。
3. 其余：eslint 不认 setTimeout/URLSearchParams 全局（改 timers/promises 与手动编码）；cache clear-website 为位置参数；lint 未用变量三次出现（同款模式第三次，已在 verification.md 记录在案）。
4. 体检阶段两次误报自纠：搜索页 `<article>` 计数与表单 label 检测（单引号/嵌套结构）——检测器必须先对已知正确样本自校准再下结论。
