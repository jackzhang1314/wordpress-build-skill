## 原生链路

1. **连接与发现**：`doctor` 读取真实账号权限、active block theme、116 个注册块、页面模板设置和实际内容模型。确认站点已有 `oct_product` / `oct_case`，没有安装或注册新内容模型。
2. **素材**：`upload-media` 上传公有领域 JPEG，回读标题、alt、caption；实际媒体 ID 29。页面图像块使用该 ID，匿名前台图片实际加载且 alt 一致。
3. **CSV/CPT**：用 `import-plan/import-apply` 导入 3 条挖掘机询盘 profile，稳定键为 `TD-MINI`、`TD-CRAWLER`、`TD-LONGREACH`；实际产品 ID 30/31/32。先建草稿并核对，再显式发布。
4. **原生字段绑定**：产品正文包含 `core/post-meta` 绑定，读取 `oct_model`、`oct_material`、`oct_moq`、`oct_lead_time`。匿名详情页显示 CSV 中的 class/use case/minimum order/lead time，不是 fallback。
5. **页面**：`build --plan` 创建 Home/Products/Process/Contact 四个草稿，页面 ID 36–39。块集合只使用受控核心块：group、heading、paragraph、columns、image、button、query、post-title、post-excerpt、pagination、details、table。
6. **浏览器改稿**：草稿截图发现三列/四列在主题内容宽度下文字过窄，且流程阅读顺序被列内堆叠打乱。用 `read-page/page-edit-plan/page-edit-apply` 改成两列分组和更短文案，完整前后稿留在任务目录。
7. **发布**：草稿预览和编辑器检查通过后执行 `build --publish`。工具只改状态并设置站点标题、描述和首页；后续改稿保留发布状态。
8. **导航**：读取真实 template part 后，用唯一导航原文生成计划，替换 header 和 footer 两个原生 navigation block。页眉为 Home / Excavators / How It Works / Contact；页脚两个竖向菜单也指向同一组发布页。
9. **产品详情模板**：默认 single 模板暴露“Written by in”和无关 “More posts”。这是已知缺口。用 `single-template-plan/single-template-apply` 创建 `twentytwentyfive//single-oct_product`，保留真实 header/footer，关闭未用特色图，并加原生 CTA。匿名详情页不再显示作者行和无关文章。

## 顺带验证的工程语义

- **计划固定**：整站 build 后改页面，不改原计划直接 `--publish` 仍按任务里的页面状态发布；后续正式改稿走 page-edit 计划。
- **依赖变化**：同一 template part 的两个 footer navigation 计划先生成、后依次应用时，第一个会因部件哈希变化拒绝；必须应用一个后重新读取并生成下一个计划。本次第二个导航也按此重新计划后通过。
- **测试隔离**：旧 CMS 测试产品 22/24 是 `oct_product`，会出现在无过滤 Query Loop。用显式 content-plan 改回 draft，而不是删除；演示目录因此只显示 3 条挖掘机 profile。

## 仍不能外推的能力

- 目录块目前只有 `postType/perPage`，没有 taxonomy/term/search 过滤；混用同类内容时要么分离内容类型，要么继续显式处理测试数据。下一步可小步增加受控 query 过滤。
- 本次只覆盖 Twenty Twenty-Five 与 loopback WordPress 7.1；经典主题、HTTPS、子目录/托管差异、真实应用密码策略和客户内容模型仍需逐站 doctor。
- 表单创建/邮件送达、SEO 插件、证书/合规材料、真实公司资料和多语言仍没有实现或验收。
- 专用 CPT 模板适配的是默认 hierarchy；每篇单独模板、更具体的 hierarchy、第三方主题模板锁定仍会覆盖，必须按站点实际结构核对。
