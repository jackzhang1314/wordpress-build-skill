时间：2026-09-20，Asia/Shanghai。范围：Codex 为新建 B2B 网站生成结构和样式，后台维护产品、分类及可复用模板；不用第三方页面编辑器。

**建议：以原生区块主题作为下一阶段主线，保留独立业务插件、ACF 字段 UI 和既有询盘链路。PHP 混合方案保留为已运行的基线。** 选择依据是原生编辑、模板组合与后续扩展的契合度，而非“WordPress 官方认证最优”、速度优势或视觉质量已经达标。

## 发现并修正的问题

1. 区块主题起初站点标题也输出 H1，造成一页两个 H1；改为非标题站点名称。
2. 联系页原正文已有表单 shortcode，又放动态表单块，导致表单重复；增加单一表单渲染来源判断，重新提交后仅新增一条记录和一封本地邮件。
3. 此 WordPress 版本的产品模板选择界面最初展示了归档等不适用模板；仅在产品模板查询中筛选两套批准模板，保留 Site Editor 的完整管理能力。
4. 复制的经典主题 CSS 在移动端隐藏了原生 Navigation；为区块导航修正作用域并实测菜单交互。说明“无横向溢出”不是移动端功能验收。
5. 数据库模板会遮蔽同名文件更新。已验证来源检测、显式合并和保留用户修改；不能自动删除用户覆盖来让部署生效。
6. 最初后台回显断言曾读到旧值；改用唯一标记、等待服务端保存和新的浏览器导航复核后，两边通过。未把未经证明的缓存原因或绑定故障写成结论。测试修改已恢复。

## 性能与视觉的边界

本轮仅采集同机热请求 HTML 总耗时，每路由 5 次；未测生产缓存、网络、LCP/INP 或完整浏览器性能预算。

| 路由 | A HTML / 中位耗时 | B HTML / 中位耗时 |
| --- | --- | --- |
| 首页 | 41,660 B / 60.3 ms | 76,458 B / 64.0 ms |
| 产品目录 | 40,190 B / 41.2 ms | 78,172 B / 51.0 ms |
| 产品详情 | 38,709 B / 45.9 ms | 68,807 B / 47.6 ms |

本次没有证据说明区块方案更快；HTML 体积反而更大。样本很小、运行顺序固定，首页内容也非完全等价，不做统计或普遍性推断。选区块的理由是编辑与模板能力。

截图仍有大量演示图片复用、基础排版、简化页脚和未打磨的细节。B 也未完成行业方案、About 等全站页面的同等深度设计。**两者都没有被认定为优秀 B2B 视觉交付。** 本次没有以主观分数宣称某方案更美观。

## 对架构的实际决策

1. 继续共用业务插件拥有的 CPT/Taxonomy、产品字段、媒体和询盘 ID。ACF 免费版保留为字段编辑 UI；没有引入 ACF PRO Blocks 或第三方页面编辑器。
2. 区块主题负责 `theme.json`、原生模板/部件与样式；Codex 生成和维护设计，运营默认编辑内容与选择批准的模板。
3. 标题、图片、正文、列表优先核心块；本原型仅将规格、产品 CTA、分类筛选等封为 5 个小动态块。简单标量通过受控绑定读既有 ACF 数据，未复制一套同名 meta。
4. 产品模板采用原生 customTemplates；分类采用真实 taxonomy 归档、主题拥有的 term 布局字段与白名单分派。分类没有被伪装成普通 Page。
5. 正式骨架仍需补齐可插入的 Pattern 库、模板预览/编辑权限、覆盖差异工具、CLI 模板选择适配和全站验收。本次首页是原生块内容，**尚未证明 Pattern 插入与更新流程**。
6. 再完成全站、编辑器样式一致性、模板/样式/导航恢复、性能与视觉验收后，统一切换默认 Skill 和交付骨架。不能直接把实验主题改名当作生产 starter。
