# HONGDA 第二轮：运行状态保存、恢复与 Skill 沉淀

本轮只调整本地工具、验证脚本与 Skill，没有修改站点的业务模型、前台布局或客户资料，也没有覆盖第一轮阶段回执。原站保持 9464，隔离恢复站使用 9465。

## 已验证

- `recovery.json`：恢复快照时的 58 个已发布内容对象、95 个 ACF 字段值、30 个上传文件、1 条询盘；稳定 ID、正文、主图和字段保留，7 个关键路由（含真实 404）通过。数据库快照 SHA-256 未被恢复过程修改。
- `enquiry.json`：重复执行的浏览器表单测试，四个必填错误、隐藏产品上下文、无效产品拦截，成功新增一条询盘及一条本地通知。检查增量而不是假设总条数固定为 1。
- `guards.json`：恢复端口占用时拒绝启动并保留当前指针；未认证调用快照接口被拒绝。
- 四个 readiness 单元测试：实际版本与 REST namespace 同时成立才能准备完成；错误版本、仅 HTTP 成功和进程早退不能通过。另在两个真实实例检查 WordPress 7.1.1 / PHP 8.3.32。
- Skill 格式校验通过，10 个固定官方模块完整性通过；项目 lint 通过。

私有快照包含数据库、询盘、用户与本地连接材料，仅在 .lab 内保存。公开验收文件只记录数量、状态和必要技术信息。

## 保留的失败与修正

1. 第一份恢复 Blueprint 未声明 preferredVersions，实际运行 PHP 8.5.8，与 CLI 参数 8.3 不同。修正为同时指定 Blueprint 和 CLI 版本，并以实际 PHP_VERSION 核对；第一份恢复运行目录保留。
2. 早期恢复测试在服务准备完成前发起请求，收到临时重定向。增加 WordPress 运行文件、实际版本和 REST namespace 的就绪检查；仅就绪后更新最新实例指针。
3. 首次重复询盘测试在成功提交之后的回读遇到 ECONNRESET；原站已保留该记录。没有将它误记为未提交。脚本改为先保留浏览器提交回执，对只读查询做有上限的重试；后续独立测试按基线增量通过。

## 回写到 Skill

新增 `references/verification.md` 并从主 Skill 与 release 引用。收录已验证的询盘四层证据、测试增量、后台与 API 验证区分、数据快照和隔离恢复、就绪判断、版本特例和每轮经验沉淀方式。没有修改固定 vendor，没有把 HONGDA、特定端口或某个表单插件变成所有新站的要求。

## 边界

本地 SQLite 恢复不等于生产 MySQL 恢复。原有正式主机、外部邮件、品牌素材/企业事实、生产备份策略等待办保持未完成。快照依赖安装时固定的 WordPress/PHP 获取能力，不宣称全离线灾难恢复；期间应暂停编辑与上传来保证媒体/代码和数据库处于同一个业务阶段。
