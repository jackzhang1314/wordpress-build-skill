# 会话决策与研究经验

> 历史资料：本文件保留当时方案与验收，不是当前执行规范。当前仅支持新站，入口见 [系统架构](ARCHITECTURE.md) 与 [新站总编排](../.agents/skills/wordpress-builder/SKILL.md)。

整理日期：2026-09-08。依据当前会话可见请求、原项目研究方案、源码及过程记录整理；这是结构化回顾，不是逐字聊天导出。

## 1. 需求如何形成

最初面向外贸业务员、独立站运营、广告和社媒运营研究浏览器 Agent 场景：Google/地图找客、官网背调、开发信、SEO、广告搜索词分析。用户倾向把业务流程封装成 Skill，并按场景组织，降低找功能和配置的成本。

连接配置随后从单个 Skill 中拆出：一个 API 可以支持多个 Skill，所以 API 凭据由统一“连接器”设置维护，Skill 只声明所需能力和流程。Apify 地图获客、DataForSEO 数据分析、WordPress 内容发布沿用这一原则。

SEO 路线是研究优秀开源 Skill，结合浏览器工具和 DataForSEO，形成自己的细分场景包，而非不加适配地导入依赖 Codex、本地 Shell 或 MCP 进程的上游 Skill。文章写作与发布带出了 WordPress 连接器，再扩展为页面构建和站点运营。

## 3. 已经付出验证成本的经验

### Skill 不能替代执行能力

Skill 负责读取资料、规划、选择工具、判断完成条件。序列化原生块、凭据管理、REST 请求、审批、状态持久化、去重与回读应由受测的执行工具承担。只搬 SKILL.md，而不实现它调用的 `wpRead`、`wpWriteContent` 等工具，新项目无法完成写站。

### 区分“内容可编辑”和“字段可管理”

原生区块允许继续编辑正文，不自动带来结构化产品 CMS。产品型号、材质等可以存为 ACF/meta，但前端模板必须实际读取这些字段。静态参数表不能声称为动态 ACF 绑定。CPT 定义产品/案例类型，Template 定义展示结构，二者职责不同。

### 以用户站点为事实来源

先探测主题、模板、区块注册、字段 schema 和权限，保留未知状态。接口存在不等于可写；未探测到不等于不存在；使用区块编辑器不等于具备 Site Editor。不要猜模板 ID、页面链接或导航片段，不要遇到缺少自有插件就阻止普通页面创建。

### 写入与恢复要有明确证据

写入前保存预期操作；收到远端响应后先保存 ID/响应，再做回读与证据文件写入。已知响应但回读失败可以继续回读；请求结果未知不能盲目重发。`modified_gmt` 和设置 revision 目前是客户端变化检查，不是服务器原子锁。

### API 成功不是页面完成

必须分别检查正文、字段、状态回读，Gutenberg 无效区块提示，现有主题前台输出，桌面/手机布局，菜单开关和跳转。`contentMatches=true` 不能证明页面好看、表单送达或手机菜单可用。

### 简单导航要保留无关内容

当前适配采用确切片段局部替换，保留其他模板部件原文；拒绝复杂子菜单、锁定和绑定等不支持结构。使用共享导航 ref 时转为部件内联菜单会影响所有引用该部件的页面，必须在计划中说明并检查。

### 长任务需要持续保存进度

真实模型测试曾反复读取相同草稿和 Skill。已增加短正文回执、完整性标记、逐页进度指引，并把 SEO/Maps 工具改为按需加载。第二轮日志记录 11 步内 3 次上下文压缩，说明需要检查整个上下文、工具集和记忆恢复链路。**这些修复已通过局部回归，但尚不能宣称解决了完整自主建站问题。**

### 测试配置与用户配置是两件事

隔离扩展一度没有带入模型配置，用户原配置实际存在。后来已成功复用，真实模型请求也执行了。新测试项目应在运行前验证 provider/model、hasKey、授权和实际后台版本，只报告非敏感状态，不要求用户把密钥发到聊天。

### 源码、磁盘包与实际后台必须对应

本轮曾出现磁盘包已更新、实际工具回执仍显示旧列表的情况；随后测试后台改名并确认 worker URL，但侧栏 CDP 控制超时。根因未确认，不能直接认定为缓存或产品侧栏 bug。新的测试工具应在启动时验证构建身份、实际工具清单、任务创建回执，再启动长时间模型测试。

## 4. 不能继续当成当前承诺的旧方案

- 捆绑自有 WordPress 主题、要求换主题才能使用：已撤回。
- Elementor/Bricks 全站编辑是默认路线：不符合后续用户选择。
- 任意第三方主题、任意区块和任意 ACF 字段都能写：没有该能力证据。
- 应用密码用于所有 WordPress.com 托管情形：研究中已提醒认证与接口不能混用。
- 独立站建成、文章生成、表单送达和持续SEO运营“一次全部验收通过”：没有这样的验收记录。
- 本地 Playground、Node、TLS 代理、自动化浏览器是最终用户运行依赖：它们仅是开发测试工具。
